## 1. Route architecture

### Pattern 1 — `/us/{state}/{city}` (canonical tier)

- **Dynamic route:** `app/us/[state]/[city]/page.tsx` — async server shell that
  fetches providers via `getProvidersByCity` and renders `<CityPageClient>`.
- **18 static overrides** at `app/us/{state}/{city}/page.tsx` (Phoenix, LA, San
  Diego, San Francisco, Denver, Miami, Atlanta, Chicago, Boston, Detroit,
  Minneapolis, New York, Philadelphia, Austin, Dallas, Houston, San Antonio,
  Seattle). Generated by `scripts/upgrade-city-page.ts`, marked DO NOT EDIT BY HAND.
- **Canonical:** set per-page in the override's `metadata.alternates.canonical`,
  resolved through `SITE_URL`. Self-canonical, which is correct.
- **Coverage:** 530 entries in `CITY_MAPPING`.

### Pattern 2 — `/us/metro/{slug}` (already consolidated)

- **Dynamic route:** `app/us/metro/[metro]/page.tsx` + `layout.tsx`.
- 50 metros in `data/top-metros.ts`.
- **Canonical logic lives in `lib/seo/metroCanonical.ts`.** `metroHref()` resolves
  every internal link to the city page where one exists, so **there are zero
  internal `href="/us/metro/"` links anywhere in the codebase** (verified by grep).
- **48 of 50 metros cross-canonical to their city page.** Only `new-york-city` and
  `washington-dc` self-canonical, deliberately — neither has a city-page twin, so
  redirecting either would 404.
- 4 metros additionally hard-redirect via `next.config.mjs`: phoenix, san-antonio,
  san-diego, chicago.

### Pattern 3 — `/{city}-{st}/{slug}` (the actual problem)

- **34 city directories** under `app/`, plus 2 intent pages
  (`mobile-phlebotomy-near-me`, `mobile-blood-draw-near-me`) that are **not** city
  duplicates and should be left alone.
- **106 page files** across 5 slugs: `mobile-phlebotomy`, `in-home-blood-draw`,
  `blood-draw-at-home`, `lab-draw-at-home`, `mobile-phlebotomist`.
- Every page is `'use client'` with a **sibling `layout.tsx` supplying its own
  metadata, including a self-referencing canonical**, e.g.
  `canonical: ${SITE_URL}/boston-ma/mobile-phlebotomy`.
- This is the signal-splitter. Unlike the metro tier, these pages tell Google they
  *are* the canonical version of the content.

### Sitemap

`app/sitemap.ts` (403 lines) emits all three tiers:

- All 530 `CITY_MAPPING` cities.
- Metros, filtered by `if (metroHref(metro) !== '/us/metro/' + metro.slug) continue`
  — so only the 2 self-canonical metros are submitted. **Already correct.**
- **102 hardcoded legacy slugs.** Chicago's three and San Diego's
  `mobile-phlebotomy` were manually removed with comments explaining why; the rest
  are still being submitted.

## 3. The www redirect

**It works.** Verified live:

```
GET https://mobilephlebotomy.org/us/georgia/atlanta
  -> HTTP/1.1 308 Permanent Redirect
  -> Location: https://www.mobilephlebotomy.org/us/georgia/atlanta
```

Two mechanisms exist and neither is missing:

1. `next.config.mjs` — a `redirects()` entry matching `host: mobilephlebotomy.org`
   with `permanent: true` (Next.js emits 308).
2. `middleware.ts` — deliberately does **not** handle the apex, with a comment
   explaining that Vercel's platform-level domain redirect answers first and a
   second rule would only create a redirect chain.

Middleware *does* handle two other host duplicates: the production Vercel alias
`mobile-phlebotomy-directory.vercel.app` 308s to www, and any other `*.vercel.app`
preview host gets `X-Robots-Tag: noindex, nofollow`.

**Conclusion: the 7 non-www pages in GSC are historical.** They were indexed
before the redirect existed, and Search Console retains them until recrawl. No
code change will help beyond what is already in place. Requesting re-indexing for
those 7 URLs in GSC is the only useful action, and it is optional.

## 5. The 18 static overrides

**They are not a fourth URL pattern and require no consolidation.** Each occupies
the *same* URL as the canonical dynamic route and takes precedence over it (static
beats dynamic in Next.js routing). Each renders `<CityPage>` — the dynamic
component — and wraps it with:

- server-rendered `metadata` including a self-referencing canonical
- three JSON-LD blocks (LocalBusiness, FAQPage, BreadcrumbList)
- `CITY_LONGFORM` prose where it exists
- `<ProvidersInCity>` and `<NearbyCities>` SEO sections

None is a thin duplicate. All 18 are strictly additive to the page they override
and all should be preserved. **Leave them out of scope for Phase 2**, except for
regenerating any whose provider counts shift.

`CITY_LONGFORM` currently holds **exactly 4 keys** — `illinois/chicago`,
`california/san-diego`, `arizona/phoenix`, `texas/san-antonio` — which are
precisely the 4 cities already consolidated. That is the established pattern and
the most important precedent in this codebase: **port the prose into
`data/city-longform.ts`, then redirect.**

## 8. Risks

1. **8 cities would 404** if redirected without new city pages. Hard blocker.
2. **Content loss on 9 pages** unless the prose is ported into `CITY_LONGFORM`
   first. The precedent and the mechanism both already exist.
3. **Redirect chains.** `/chicago-il/mobile-phlebotomy` already redirects and the
   homepage still links to it. Any new redirect must point at the *final*
   canonical, never at another redirect — repoint internal links in the same change.
4. **A duplicate may currently outrank its canonical.** This cannot be verified
   from the codebase; it needs GSC per-URL position data. Before redirecting the 9
   content-rich pages, check each pair's position — where the legacy page ranks
   materially higher, port the content first and stage that redirect separately so
   any regression is attributable.
5. **The sitemap must change in the same deploy.** Submitting a URL that 301s
   wastes crawl budget and muddies the consolidation signal — the existing Chicago
   and San Diego comments in `app/sitemap.ts` say exactly this.
6. **`bronx`, `brooklyn` and `staten-island` map to `/us/new-york/{borough}`.**
   They exist in `CITY_MAPPING`, but I did not verify those pages render live.
   Confirm before trusting those 9 redirects.
7. **Low impact ceiling.** The whole legacy tier is 105 clicks. Consolidation is
   worth doing for signal hygiene, but the traffic upside is modest — the 358
   `/us/` pages already carry 557 clicks, and the larger problem is that most city
   pages sit at position 20–36 for reasons unrelated to duplication.

## 9. Recommended implementation

**Canonical pattern: `/us/{state}/{city}`.** It is the only tier with a generator
producing real provider counts and LocalBusiness / FAQPage / BreadcrumbList
schema; it has 530 pages against the legacy tier's 34; and both prior
consolidations already moved in this direction.

**Mechanism: `next.config.mjs` `redirects()`.**

| Approach | For | Against |
|---|---|---|
| **`next.config.mjs`** ✅ | Already holds all 14 existing redirects — one place to look; evaluated at the edge before rendering; reviewable as a static list in the diff | Needs a deploy to change; the list grows long |
| `middleware.ts` | Pattern-matching could collapse 78 entries into one rule | Runs on every request; this file already carries host handling, rate limiting and URL normalisation — adding SEO redirects makes a critical path harder to reason about |
| `vercel.json` | Platform-level, fastest | Currently holds only crons; splitting redirects across two files means future work must check both. **Avoid.** |

Consistency with the 14 redirects already in `next.config.mjs` is worth more than
the brevity a middleware pattern would buy.

**Suggested Phase 2 sequence:**

1. Port the 9 content-rich pages' prose into `data/city-longform.ts`.
2. Repoint the 13 homepage links (plus `SearchContent`, `StatePageClient`, and the
   metro page) at canonical `/us/` URLs.
3. Add the 78 redirects to `next.config.mjs`, generated via
   `scripts/discover-legacy-city-routes.ts --emit` rather than hand-written.
4. Remove the corresponding 78 entries from `app/sitemap.ts`.
5. Optionally delete the redirected page directories — redirects fire first, so
   this is tidiness, not correctness.
6. Decide (a) or (b) for the 8 blocked cities and handle them separately.
7. **Leave the metro tier alone.** It is already correct.
